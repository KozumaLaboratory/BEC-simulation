## 2. 言語と書き方

**TypeScript。** 旧版の ES3 制約（`var` しか使えない、`forEach` 不可、…）は
**全部消えた**。ただし装置の実行環境は Windows 側なので、ここで動かして確かめる
ことはできない。

### 単位が型になっている

```typescript
import { deg, G, G_cm, Hz, kHz, mG, MHz, ms, mW, nW, s, uG, us, uW, V, W } from ".../units.ts";

const hold = 30 * uG;          // 磁場
const frequency = 80 * Hz;     // 周波数
euv.fort({ h: 87 * mW, v: 90 * mW }, 200 * ms);
```

`Watts` / `Hertz` は branded type なので、`power / mW` のように**単位で割って
裸の数にしてから**係数に掛ける（`calibration.volts.*` がその形）。
無次元量（飽和パラメータ `s = I/I_sat`、gain 倍率、較正比）には単位を付けない。

### 書ける細かさ ── **値を決める前にこれを知っていること**

`euv3.ts` の冒頭に書いてある。**これより細かい桁は書いても出ない。**

| 経路 | 送り方 | 刻み |
|---|---|---|
| `euv.field.set` / `ramp` | 2 数 | 小数 3 桁 = **1 mV** に丸められる |
| `euv.field.weak.*` | 文字列 | 丸めないが、DAC が **1 LSB = 305 µV**（NI PXIe-6738、16 bit / ±10 V） |

gain LOW での磁場に直すと:

| 軸 | 1 mV | 1 LSB |
|---|---|---|
| west | 2.2 µG | 0.66 µG |
| south | 4.1 µG | 1.3 µG |
| vertical | 6.3 µG | 1.9 µG |

⇒ **旧 JS 期の 5 桁指定（`12.60126 * uG` など）は装置に届いていない。**
`euv3.ts` の `weak` モードにその字面が残っているが、ファイル自身が
「r14 の字面をそのまま残しているだけで、装置には届いていない」と注記している。

## 3. `euv` の API（`euv3.ts` の使われ方からの推測）

**ライブラリの定義を読んで書いたものではない。**確かめるには Windows 側の
`lib/euv.ts` を見ること。

| 呼び方 | 意味 |
|---|---|
| `euv.step(name, duration, fn)` | 1 段。`fn` の中で磁場などを指示する |
| `euv.fort({h, v, s}, duration, note?)` | FORT のパワーを指定して 1 段進む |
| `euv.fortOff(narrow)` | FORT を切る |
| `euv.field.set(spec)` / `.ramp(spec)` | 磁場（2 数、1 mV 刻み） |
| `euv.field.weak.set/ramp/parabola(spec, …)` | 弱磁場（文字列、丸めなし） |
| `euv.field.cone({magnitude, theta})` | **円錐面上を回る磁場。**返り値に `.move({theta, frequency, magnitude, rampUp})` と `.hold()`。方位角の位相は段をまたいで繋がる |
| `euv.scan(values)` | ショットごとに配列を巡回して 1 つ返す |
| `euv.shot` | ショット番号 |
| `euv.clock` | 現在時刻（TOF の起点に使う） |
| `euv.log(msg)` | ログ |
| `euv.stopHere()` | ここで止めて撮る（下の段を飛ばす） |
| `euv.ports.{camera, imaging460, imaging583, bragg, scopeTrigger}` | ポート |
| `euv.daq.setDigitalToPulseMode(pin, delay, width)` | 生の DAQ |
| `spherical(magnitude, polar, azimuth)` | 極座標 → `FieldSpec` |
| `imagingAxis(calibration)` | 撮像の量子化軸 |

`steps.ts` の高水準ステップ: `motLoad` `compress` `loadFort` `mot2Off` `biasUp`
`shrinkFort` `mot1Off` `releaseAndImage`。

`FieldSpec` に渡せるもの（観測できた範囲）: `{ x, y, z, gradient, gain: "high"|"low",
zeroOverride }`。

## 5. 触れるノブ

### 最上位（`const TRAP` / `const MODE` / `const SPIN_SEPARATION` の 3 行）

```typescript
const TRAP = "hh" as Trap;              // "hh" = hFORT × sFORT（基本）/ "vh" = hFORT × vFORT
const MODE = "barnett" as Mode;         // "bec" | "weak" | "ground" | "barnett"
const SPIN_SEPARATION = true;           // Stern-Gerlach で m_F を空間に分けるか
```

**`MODE = "bec"` は BEC をそのまま撮るだけ**（実験の段を全部飛ばす）。

### 蒸発ランプ（`euv.fort(` が並ぶ 8 行 + `if (TRAP === "hh")` の最終トラップ）

```typescript
euv.fort({ h: 4 * W,    v: 1.8 * W  }, 300 * ms);
euv.fort({ h: 2 * W,    v: 1.7 * W  }, 500 * ms);
euv.fort({ h: 1 * W,    v: 1.6 * W  }, 400 * ms);
euv.fort({ h: 560 * mW, v: 1.5 * W  }, 600 * ms); // ここで hFORT が枯れる
euv.fort({ h: 260 * mW, v: 1.4 * W  }, 300 * ms);
euv.fort({ h: 160 * mW, v: 1 * W    }, 200 * ms); // ここで一部 BEC
euv.fort({ h: 120 * mW, v: 600 * mW }, 100 * ms);
euv.fort({ h: 87 * mW,  v: 90 * mW  }, 200 * ms); // -> BEC
```

上限は `calibration.volts` のコメント: **hFORT 6.0 W / vFORT 5.5 W / sFORT 2.0 W**。
**下げ方向にしか掃かない**こと（§7-A）。

### `MODE = "barnett"`（`if (MODE === "barnett")` のブロック）

```typescript
const frequency = 80 * Hz;              // 回転周波数
const tilt = 35 * deg;                  // 回転中の極角（+z から）
const hold = 30 * uG;                   // 円錐を閉じたあとの保持磁場
const sense = euv.scan([+1, -1, 0]);    // +1 右回り / -1 左回り / 0 静止（対照）
```

段: 傾ける 20 ms → 立ち上げ 100 ms → 回転 250 ms → 円錐を閉じる 200 ms →
保持 50 ms。`cone` が方位角の位相を段をまたいで保持する。

**共鳴の注意（ファイルが自分で警告する）**: 回転座標系で共鳴するのは
`Bz = ω/γ_F`。80 Hz なら **49.2 µG**。いまの `hold = 30 µG` は
**通り越して 1.6 倍下**。共鳴で止めたいなら `hold = 49.2 * uG` にするか
`frequency = 48.8 * Hz` にする。**実験上の判断なので触られていない。**

### `MODE = "ground"`（`if (MODE === "ground")` のブロック。修論 5.2.1 / 6.1 の EdH 手順）

```typescript
const hold = 120 * uG;                  // 到達磁場（修論 6.1 は 63 µG、20260903 は 120 µG）
const parabolaTime = 200 * ms;
const angles = [-16, -8, 0, 8, 16] * deg;   // 原子位置での実効回転角
const tilt = tiltAtom * (10 / 16);          // 装置に指示する角（較正）
const probe = -10*ms + 1*ms * (floor(shot/5) % 41);  // 撮像時刻（hold 到達を t=0）
```

**2 重スキャン**: 回転角 5 点を回すごとに撮像時刻を 1 ms 進める（41 点）→ 205 ショット周期。

**較正の注意**: プログラム 10° 指定 → 原子位置 16°（修論 5.1.2）。**較正点はこの 1 点
だけ**なので ±32° は外挿。較正を掛けないなら `10/16` を `1` にする。

### `MODE = "weak"`（`if (MODE === "weak")` のブロック）

300 ms の弱磁場保持。**指定の 5 桁は装置に届いていない**（§2）。

### 較正（`export const calibration` のブロック）

`calibration` オブジェクトに全部入っている。再校正のときはここ 1 か所。
`measured` 配列が「いつ何を測ったか」の履歴。

## 6. 検証 ── 旧ハーネスは使えない。代わりにやること

JS 期は「ホストを全部スタブして DAQ 呼び出し列を diff する」で担保していた。
**TS + 外部ライブラリではそれが成り立たない**（§0）。いまできるのは:

1. **Windows 側で型検査を通す。** 単位が型なので、`30 * uG` を `30 * mG` と
   書き間違えたら**コンパイルで落ちる**。これは JS 期に無かった強い保証。
2. **`euv.stopHere()` で段階的に撮る。** 途中まで走らせて実際に原子を見るのが
   一番確実。`euv3.ts` はそれを前提にコメントが書かれている。
3. **`euv.log` / `scopeTrigger` を使う。** `barnett` は共鳴のずれを自分で log に
   出す。`ground` は放物線ランプの開始でオシロトリガを上げる。
4. **`euv.scan` に対照を入れる。** `barnett` の `[+1, -1, 0]` がその形 ──
   ±Ω と静止を同じ条件で撮るので、系の状態の違いで説明が付かなくなる。

**旧ハーネスが捕まえていたもの**（実バグ 10 件）のうち、型検査で自動的に消えた
ものと、消えていないものがある:

| 旧ハーネスが捕まえた種類 | いま |
|---|---|
| 単位・スケールの取り違え | **型が捕まえる** |
| 方程式文字列の不正な形（`+-`、先頭の単項マイナス） | **消滅**（文字列を組まなくなった） |
| 単調性の破れ（トラップの締め直し） | **捕まらない。** 人が見る（§7-A） |
| 意図しない DAQ 呼び出しの増減 | **捕まらない。** 型は呼ぶ順番を見ない |
| σ の扱い・門の設計 | **捕まらない。** そもそも euv3.ts に最適化ループが無い |

## 7. 落とし穴

### A. 単調性 ── トラップの締め直しは装置に出してはいけない

FORT は下げ方向にしか掃かない前提で校正されており、途中で締め直すと断熱圧縮で
加熱する。**旧版はコードで射影していたが、`euv3.ts` は直書きなので人が守る。**
`euv.fort(...)` の h / v が前の行より大きくなっていないか目で確かめること。

モデル側にも同じ警告がある: 事前研究の最適解のうち「トラップを締め直す族」
（`optimize_ramp_coordinate`）は guide 自身が「実行するスケジュールに使うな」と
明示している。**転記してはいけない**（§10）。

### B. Stern-Gerlach ── 何を測るかで要否が逆になる

`SPIN_SEPARATION` が SG（勾配 9.0164 G/cm を 6 ms）を出すかを決める。
実装は `releaseAndImage` に渡す `sternGerlach` フィールド（grep するならこれ）。

- **磁化・m_F 分布を見るなら必要**（`barnett` / `ground` / `weak`）。**いまは `true`。**
- **雲の大きさ・原子数で最適化するなら切る。** SG が入った像は m 成分に分かれた
  13 個の塊で、**単峰 Gauss フィットの幅は雲の大きさではなく分離幅**になる。
  位相空間密度の代理量 `N/(w_x·w_y)^{3/2}` は無意味になる。
- **MOT の原子数だけ見るときは必ず切る。** 勾配 9 G/cm を 6 ms かけると原子が飛ぶ。
  `euv.stopHere()` を戻すときは `SPIN_SEPARATION = false` も同時に。
  （`euv3.ts` の `euv.stopHere()` の直前コメントが同じ注意を書いている）

**しかも気づけない**: SG が入った像でも単峰フィットは数字を返すので、表は普通に
見える。**解析に渡すデータには SG の有無を必ず記録し、混ぜないこと。**

### C. gain LOW の零点に残留磁場の打ち消しが入っていない

r14 は gain LOW の零点に補正を持っていた（2026-09-03 に EdH を見ながら調整）:

```
west -0.0020 V / south -0.0016 V / vertical +0.0010 V
```

`euv3.ts` の `calibration.coil.zero` は**生の零点だけ**なので、**弱磁場が数 µG
ずれている**。1 mV = 2.2〜6.3 µG（§2）なので、これは 30 µG や 63 µG の実験では
**10 % 級の系統誤差**。

**入れると `barnett`（旧 jar と一致確認済み）の電文も動く**ので、入れるなら別に
決めること。`euv3.ts` の `ground` ブロック末尾（`★ r14 は gain LOW の零点に` で始まる）に同じ注記がある。

### D. 回転共鳴 ω/γ_F は g_F で決まる。g_J ではない

**2026-09-05 まで g_J の 2.790 MHz/G を使っていて、ω/γ が 12/7 倍ずれていた。**

弱磁場では F が良い量子数で、BEC がいるのは F = 6（m_F = −6 に偏極）。F = 6 は
伸びきった多重項なので

```
g_F = g_J · J/F = 1.9934 × (7/2)/6 = 1.9934 × 7/12 = 1.1628
γ_F = g_F μ_B/h = 1.1628 × 1.39962 MHz/G = 1.627 MHz/G
```

（リポジトリの `CLAUDE.md` の `g_F ≈ 1.163` と一致。検算済み 2026-09-06）

⇒ 80 Hz の共鳴は 49.2 µG。**古い値で計算した磁場が残っていないか確かめること。**

### E. σ を batch をまたいで持ち込んではいけない

σ は 2 通りの意味で変わる: 推定のばらつきと、**σ 自体が動く**（真空度・ロック・
MOT の重なり）。後者は補正で扱えない。しかも代償が相関する ── σ が低く出た日は
**全ブロックの判定が一律に緩む**ので、1 回では絶対に見えない。

⇒ **σ を測るデータと判定するデータを同じ batch に入れる。** 具体的には
基準点を数ショットごとに挟む（例: `[基準点, +δ, −δ]` の 3 周期）。1/3 のショットを
払うが、払わないと σ とドリフトを事後に分離できず**その batch は解析不能**になる。

2026-09-03 の実測では σ が軸の間で 8.1 %〜12.9 % に動いていた（同じ 17 分の中で）。

### F. 差の判定は「差の」標準誤差で

`K·σ/√n` と書くと比較相手の誤差を無視することになり、実効有意水準が 3σ から
2.45σ に落ちる。正しくは `σ·√(2/n)`。この誤りで誤判定が期待 1.1 件に対して
実測 2〜6 件出た（JS 期の合成応答での実測）。

### G. `runs/**/*.csv` は `.gitignore` で無視される

前提は「結果 CSV は jld2 から再生成できる」。**実験データではこれが偽**なので
`!runs/eu_lab/data/*.csv` の否定を入れてある（`.gitignore`）。
**別の場所にデータを置くなら否定も足すこと。** 忘れると測定の唯一の記録が
コミットされない。同じ病気が過去に 2 度起きている。

### H. 較正点が 1 点しかない外挿

`ground` の回転角較正は「プログラム 10° → 原子位置 16°」の**1 点だけ**。
`angles` の ±16° は 10/16 を掛けて ±10° 指定になるが、±32° まで振るなら
**外挿していることを明示すること**。

### 結果

```
hFORT 段1 ±15 %:  Δ = +1.3 %,  Δ/SE = +1.23  →  ゼロ
```

SE = 1.06 %、**3σ 検出限界 3.2 %**。つまり **「±15 % の効果は 3.2 % より小さい」
という上限**であって非結果ではない。1.3 % を有意にするには各腕 236 発
（約 1400 ショット）必要 ── 割に合わない。

**説明候補（未検証）**: 段 1 は 4 W で終わり、ランプ終端は 87 mW ── 46 倍深い。
そこでの ±15 % は分布の裾をほとんど削らない。**陽性対照が無いので推測に留まる**（§9-1）。

### 診断で見つかったこと

- **幅が 0.1 刻みで量子化されている。** `wx` の取る値は 4.5/4.6/…/5.0 だけで、
  刻み 2.1 % が**ばらつきのほぼ全部**。`(wx·wy)^1.5` はこれを 1.5 乗で増幅する
  ので、二乗和で見ると**幅の項（22.3）が N の項（16.8）より大きくノイズを持ち込む**。
- **`fitNumberX / fitNumberY = 0.921 ± 0.018`。** 8 % の系統的な食い違い。
  ばらつきが小さいのでフィットの非対称。

## 9. 実験の候補

### 1. 蒸発の陽性対照 ── 最優先（`MODE = "bec"`, `SPIN_SEPARATION = false`）

**いま一番欠けているもの。**「効かないノブ」と「見えていない測定系」は同じ出力を
出す。物理的に応答が保証された量を、**同じ batch の中で**振る。

**最終段の power**（`euv.fort({ h: 87 * mW, ... })` の 87 mW）は最終トラップ深さ
そのものなので応答が保証される。ここが動かなければ測定系か目的関数が壊れている。
基準点を挟んで ±15 %、各腕 15 発程度で 45 ショット / 8 分。

**これを飛ばして先に進んではいけない。**

### 2. Barnett の共鳴（`MODE = "barnett"`）

いまの設定は `frequency = 80 Hz`, `hold = 30 µG` で、**共鳴 49.2 µG を通り越して
1.6 倍下**。`hold` を 49.2 µG にする／`frequency` を 48.8 Hz にする／いまのまま、
の 3 通りは**違う実験**。`euv.scan([+1,-1,0])` の対照は既に入っている。

`hold` を動かす前に §7-C（零点の補正が入っていない）を片付けるか、
**入っていないことを承知で読む**かを決めること ── 数 µG のずれは 30 µG に対して
10 % 級。

### 3. `ground`（EdH、修論 5.2.1 / 6.1）

2 重スキャンで 205 ショット周期（角度 5 × 撮像時刻 41）。約 34 分。
較正が 1 点外挿であること（§7-H）を結果に添えること。

### 4. 蒸発ランプそのもの

事前研究（0-D モデル）は「**弾性衝突率が最高のロード直後に深さを速く落とす**」で
3.48× と言う（検証型 B、§10）。`euv.fort` の最初の数行を短く・低くする方向。
**1 で陽性対照が出てから**。

### なぜモデルが裁定者になれないか

Eu の K₃ は**未測定で [1e-42, 1e-40] の 100 倍の帯**があり、絶対原子数はその帯の
どこを採るかで動く。guide の値（ab-initio 1e-41）は唯一の実測終点 5.02e4
（PRL 129, 223401）を**過大評価している**。Miyazawa 2021 の直接測定 1.2e-41 対
BEC-fit 4.6e-42 で **~2.6× の系統差**もある。

⇒ **機構（どの方向に振るか）は借りる。大きさは借りない。的は測定値。**

### Barnett（回転駆動）

磁場方向を z まわりに角速度 Ω で回すとスピンが追従するぶん角運動量が注入され、
回転を止めて向きを z に戻し |B| を十分弱くすれば L_z が spin に変換されて
⟨F_z⟩ が動く。

- **回転座標系での共鳴**: `Bz = ω/γ_F`。γ_F = 1.627 MHz/G（§7-D）。
- **水平 2 コイルは直交していない**（west −10°, south +98°、`calibration.coil.axis`）。
  `field.cone` がそれを吸収する。
- **断熱性は圧倒的に満たされる**: 1 G での Larmor は ~1e7 rad/s、量子化軸の回転は
  ~1e3 rad/s（`rotate quantization axis -> +z` の段のコメント）。⇒ 段の長さは断熱性ではなく**コイルの追従**で決まる。

シミュレーション側の同じ段割りは `runs/eu_barnett_redo/run_core.jl`。
台帳は `docs/campaign/claims.toml` の `barnett-*` 6 行。

## 11. 測定規律

リポジトリの `CLAUDE.md` にある一般則のうち、この装置で実際に効いたもの。

1. **走らせる前に感度表。** 2 点／(パラメータ, 観測量) で、観測量の不確かさで
   規格化する。**ほとんどの軸はゼロになるのが正常で、それが結果。**
2. **陽性対照が無い null は証拠でない。**（§9-1）
3. **系統誤差を残差より先に。** 押さえた軸の系統も含む。
4. **判定条件を投入前に決める。** 走り終えてから解釈を選ぶのは測定ではない。
5. **1 arm 走らせて報告。** 続けて 2 本撮ると前提の誤りが 2 本ぶん隠れる。
6. **離散観測量を好む。** リング数・巻き数・渦の数・対称性の有無は誤差棒も校正も
   持たない。
7. **正規化は測定上の選択。何を割り落としたかを言う。**
8. **測定を「意外」と呼ぶ前に理論を当たれ。** 説明できない 2 倍以上は報告する
   発見ではなく検索の合図。（§7-D の 12/7 がまさにこれ）

## 12. TS 移行で何が変わったか（旧 CONTEXT.md との対照）

| 旧版の記述 | いま |
|---|---|
| ES3 の制約（`var` のみ、`forEach` 不可…） | **無効。** TypeScript |
| ホストが注入するグローバル 8 つ | **無効。** 型付きの `euv` オブジェクト（§3） |
| 1 ファイル制約 | **無効。** モジュール分割済み（ただし lib はここに無い） |
| `EVAP_OPT_*` の蒸発最適化ループ | **euv3.ts に存在しない。** 移植されていない |
| `BR_*` の Barnett ブロック | **lib の `field.cone` に置き換わった。**`MODE = "barnett"` |
| 方程式文字列（`+-`、パーサの文法） | **消滅。** 文字列を組まなくなった |
| トレースハーネスによる DAQ 列の diff | **使えない**（lib が無い）。代わりに型検査（§6） |
| SG の自動切替（`EVAP_SG_MODE`） | **手動。**`SPIN_SEPARATION` を人が合わせる（§7-B） |
| LOW gain の倍率が不明 | **判明。**`calibration.coil.lowGain = 101` |
| 書ける細かさが不明 | **判明。** 1 mV / 1 LSB = 305 µV（§2） |
| g_F の値 | **修正済み。** 1.1628（2026-09-05 まで g_J を使っていた、§7-D） |

**残ったもの**: 落とし穴の物理側（§7-A/B/E/F/G）、実測値（§8）、事前研究（§10）、
測定規律（§11）。
