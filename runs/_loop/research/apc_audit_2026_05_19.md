# APC Audit (2026-05-19) — Verdict: Pull the Hook

External reviewer (arXiv:2602.18922) flagged Agentic Plan Caching as
achieving 0-12% accuracy on personal-AI-agent benchmarks. The SpinorBEC
loop's APC hook claimed 30-50% cost reduction per the original paper
(arXiv:2506.14852). This audit checks whether the SpinorBEC instance
is actually realizing the benefit.

## Method

Sampled the cache entries via `python3 .claude/scripts/contract_cache.py list`,
then for the most-used key `physics::verify-claim::Execute` (9 seen, T27-T100):
- Compared the cached `template_skeleton` field shape vs actual §6 contracts
  extracted from `runs/_loop/director/turn_${N}.md` for the 3 sample turns
- Searched director.md outputs for evidence of actual lookup invocation
- Verified director's tool grants in `.claude/agents/director.md` frontmatter

## Finding 1 (decisive): director has NO Bash tool

`tools: Read, Grep, Glob, WebFetch, WebSearch, Write`

The §B1 directive in director.md tells director to call
`python3 .claude/scripts/contract_cache.py lookup --kind ... --template ... --stage ...`
but **director cannot execute this command**. 6 director turns
(T92-T96 + 1) include the lookup wording, but the language is always
hypothetical: *"... would return verify-claim Hypothesize cached
skeleton at n_seen >= 2 ... USE the cached skeleton: preserve ..."*

The director is confabulating: it pretends to have looked up the cache
and writes what it would have done, but no actual lookup happens. The
cache is being EXTRACTED post-step by `contract_cache.py extract` but
never INFORMS the director's input. Claimed "30-50% cost reduction" is
not realized in this deployment.

## Finding 2 (decisive): skeleton ≠ class-generic, it's "last-seen"

Comparison of `physics::verify-claim::Execute` cached skeleton vs
3 actual contracts that should have matched:

| Turn | Investigation | observable_manifest.required (head) | n_criteria | n_failure_modes |
|------|---------------|-------------------------------------|-----------|-----------------|
| T27 | barnett | `["norm(t) per Omega", "<F_z>(t) per Omega", "<F_x>, <F_y>", ...]` | 4 | 8 |
| T35 | yan-li-saito | `["precondition_check_exit_code_zero", "jld2_artifact_exists", "f1_n_max_in_D0_extracted", ...]` | 9 | 11 |
| T100 | tdhfb-phase2 | `["experiment_kind", "investigation_kind", "investigation_id", "stage_advancing_to", "flow_template"]` | 18 | 5 |
| **Cached skeleton** | (same key) | **same as T100** | **18** | **5** |

The cached skeleton is **byte-equivalent to T100's contract with values
stripped** — `contract_cache.py extract` overwrites the entry on each
matching turn, so the skeleton always reflects only the most recent
match. Three earlier contracts at the same key (`barnett`, `yan-li-
saito`, `tdhfb-phase2`) have **completely different**
observable_manifests, success_criteria counts, and failure_mode shapes.

The (kind, flow_template, stage) key is too coarse — same stage across
different investigations has incompatible field schemas. Even if
director could lookup the cache, returning a tdhfb-phase2-specific
polar-phonon schema for a hypothetical next barnett-stage-Execute turn
would actively harm contract quality.

This matches arXiv:2602.18922's diagnosis: *"cache effectiveness
requires key consistency AND precision, not classification accuracy"*.

## Recommendation: pull APC hook

Specifically:
1. Remove the §B1 "APC contract template cache lookup" paragraph from
   director.md (the directive is inert at runtime).
2. Remove the `contract_cache.py extract` call from `loop.sh` post-step.
3. Keep `.claude/scripts/contract_cache.py` as an archived script
   (don't delete) — it works correctly as a deduplicator, just not as
   a director input.
4. The .claude/cache/contract_templates.json file becomes unused; can
   be left in place (small, gitignored) for historical inspection.

## What to do instead

If template reuse is a real efficiency target, the correct design
(per AI Scientist v2 pattern in the academic-frameworks research):
- Push contract structure into a JSON-schema declared in each
  investigation's metadata
- Validate output against schema, retry on schema failure
- Schema = the "template"; instances are pure data fills

This is on the 5-file rewrite track (task #39) — the rewritten
director will reference per-investigation schemas, not a class-coarse
template cache.

## Tertiary observation

The `physics::unknown::Unknown` cache key has `n_seen = 24` — these
are turns where flow_template wasn't classified at extract time.
That's 24 cache pollution entries. Confirms the key coarseness issue
and reinforces the pull recommendation.
