> 一度に読んだ時点の国勢調査であって、維持される一覧ではない。以後に増えた

## この文書の使い方（先に読む 30 秒）

**これは何か** — 「同じ誤りをまた踏んだか」を判定するための**クラスの一覧**であって、
事案の一覧ではない。事案は PR 本文にある。

**何をすればいいか** — 手を動かす前に、下の索引で**そのクラスに既にゲートがあるか**
見る。あればゲートの名前がそのまま「何が既に守られているか」の答えで、
無ければ本文の該当節に「なぜ無いか」が書いてある。

**古くなっていないか** — この表は 2026-08-22 で凍結。**現在の状態はゲートが持って
いる**（散文ではなく）。文書とゲートが食い違ったら**ゲートが正しい**。

**測り直す**（凍結後の PR を足す、または全部やり直す）:

```bash
python3 scripts/pr_mistake_census.py --verify-doc         # この文書の引用が全部解決するか
python3 scripts/pr_mistake_census.py --extract --since 447 # 凍結後の PR の「誤りを述べた行」だけ
python3 scripts/pr_mistake_census.py --counts             # キーワード分類器（別の計器。下記）
```

`--counts` は**この文書の手分類とは別の計器**で、最大 2.4 倍食い違う。
文書は「人が判断してそのクラスに入れた PR」を数え、`--counts` は「散文が regex を
踏んだ PR」を数える。regex を文書の数字に**合わせていない** — 計器を答えに合わせる
のは本文書が #144 として記録している欠陥そのもの。トレンドを見るのに使い、
「どの PR か」には使わない。

## なぜ数えたか

PR #378 が履歴そのものを測っている: **全 2638 コミットのうち 411 本（15.6 %）が
fix / retract**、月次で 9–21 % を上下し、**減少傾向は無い**。個々の PR は毎回
「原因はこれ、対策はこれ」で閉じているのに、率が下がらない。ということは、
閉じているのは**事案**であって**クラス**ではない、という仮説が立つ。

そこで PR 本文から誤りの記述を全部抜き、クラスに畳んで、**各クラスに対して
いまツリーに立っているゲートを名前で対応させた**。結果は仮説より良い:
大きいクラスの多くは実際に構造で塞がれていて、率が下がらないのは
**新しいクラスが供給され続けている**からに見える。以下、多い順。

### 最初のゲートは代理を測っていた（この節自体の訂正）

初版のゲートは「`set -e` を持つか」を測った。**それは綴りであって性質ではなく、
測った結果は両方向に外れた:**

- **正しい 2 本を告発した。** `submit_test_tier.sh` と `klaus2022/submit_stripes.sh` は
  意図的に errexit 無しで走り、`exit "$RC"` で終わる。これは errexit **より強い** —
  ジョブがスイートの実際のコードで終わるから。`-e` を付けると
  `RC=${PIPESTATUS[0]}` より前で中断して伝播が壊れる。ゲートは
  **正しいものに悪くなれと言っていた。**
- **欠陥 4 本を「債務」として駐車した。** `submit_load_check.sh` /
  `submit_gpu_smoke.sh` / `submit_mutation.sh` / `submit_test_tier_ci.sh` は
  各段の `$?` を捕まえて印字し、**最後の `echo` で終わっていた** — 赤いスイートで
  exit 0。これは債務ではなく **2026-08-08 の事案そのもの**が 4 ファイルで生きていた
  状態で、`submit_test_tier_ci.sh` は**自分のヘッダにそう書いたまま**数週間放置されていた。

「危ないから直さない」も推測だった。実際に読んだら `eu_campaign_resume.sh` だけが
本当に `-e` で壊れる（`[ "$c" -lt "$n" ] && missing=...` の偽が完全なコマンドとして 1 を返す）。
**4 本は直した**（現在 exit 0 固定なので、非ゼロを返すのは signal を足すだけ）。

### いまの性質と、ゲート

**性質: ジョブの終了ステータスがその段を反映する。** 満たし方は 2 つあり、
どちらも一級市民:(a) errexit（直接または source した兄弟経由）、
(b) 明示的なステータス経路（捕まえて `exit "$RC"`）。
そして**決して正しくない配置が 1 つ** — `$?` を捕まえたうえで別のもので終わる。
段が落ちたと知っていて成功を報告するのは、見なかったより厳密に悪いので、
これには**例外リストを付けない**。

`test/test_submit_scripts_fail_loudly.jl`（fast tier）の 5 arm:

1. **実行する** — `tsubame_setup.sh` を実際に source し `$-` を前後比較（両方向）。
   canary はガード変数に**アンカー**し、置換が着地したこと・**復元行だけに**
   当たったことを assert する（黙って何にも match しない `replace` は、
   #125 でカナリアが欠陥を素通りした形そのもの）。
2. **強制関数** — `set +e` を含む source 対象ファイルは、1 の実行プローブに
   入っていなければ赤。1 本を名指しで実行するのは、他に errexit を落とす
   preamble が無い時だけ正直だから。派生なので将来増えたら勝手に赤くなる。
3. **記録して捨てる配置は常に赤**（例外なし）。
4. **性質を満たすか、名前を挙げるか** — 両方向の集合一致。**債務バケツは廃止**。
   駐車できるバケツは、欠陥が見えるようになる場所ではなく**住む場所**だった。
   残る by-design 例外は 5 本（verdict reporter 2・advisory 1・qdel trap 付き probe 1・
   sourced preamble 1）、各行に理由。
5. **corpus の作り方をゲートする** — `#$ -l h_rt=...` は **bash にはコメント、
   UGE にはディレクティブ**なので raw text から取り、`qsub`/`julia` は
   ほぼ全スクリプトの usage コメントに出るのでコード側からのみ取る。
   これを逆にすると `submit_gpu_smoke.sh` と `submit_load_check.sh` が corpus から
   **消える** — 測定中に実際に一度やった。#322 の「regex が測定になる」と同じ形。

**`qsub -v` のコンマは意図的にゲートしていない。** `-v A=1,B=2` は 2 変数を渡す
正しい構文で、危険なのは 1 つの*値*の中のコンマ。ヘッダの usage 例からは
区別できず、正しい書き方で赤くなるゲートは切られる（本リポジトリの記録済み教訓）。
ツリーは慣習で扱っている — `;` 区切り＋要素数のクロスチェック
（`SP_CELLS` / `SP_CELLS_N`、`SB_CELLS`）。**規範として残し、ゲートにはしない。**

### `strict: true` を提案し、実測して**却下**した

最初の提案は GitHub の *Require branches to be up to date before merging*
（`required_status_checks.strict`、現在 `false`）だった。**測ったら使えない:**

| 量 | 実測 |
|---|---|
| 必須チェックの所要 | **13–15 分**（CI ワークフロー直近 12 本） |
| main へのマージ | **30 日で 387 本 / 稼働 17 日** |
| ピーク | **106 本/日**（2026-08-19）＝ **約 8 分に 1 本** |

ピーク日は PR 自身の CI が回っている 14 分の間に main が 2 回動くので、
同期し直すたびにまた古くなる。**忙しい日は事実上マージ不能**になる。
防ごうとしている被害は 450 PR 中 2 回・いずれも 1 コマンドで解消。
**対策コストが被害を上回る。** 前ターンでこれを推奨したのは、この数字を
持たずに機構の妥当性だけで判断したためで、§8 のクラスそのもの。

### 実装したのは post-merge の自動再生成

`.github/workflows/ci.yml` の `state-doc-drift` ジョブ（push × main × code 変更時のみ）:
マージ済みツリーで `generate_state.jl` を回し、差分があれば
`chore/state-doc-drift` に push して **PR を開き、赤で終わる**。
PR 作者側のコストはゼロ、発火するのは実際にこの failure mode を持つ 1 ファイルだけ。

**push ではなく PR** なのは、branch protection が 4 コンテキストを必須にしていて
`enforce_admins: true` なので、ステータスを持たない新規コミットの直 push は
拒否されるから（そもそもこの repo では何も自動着地しない）。

**このジョブ自身が監視なので、判定の到達可能性をゲートしてある** —
`test_submit_scripts_fail_loudly.jl` が ci.yml から実際の `run:` ブロックを

## 読み方

8 クラスのうち **5 つは既に構造で塞がれていて、実際に再発率が落ちている**。
本文書のために足したのは 4（台帳 2 arm）と 5（新規ゲート 5 arm＋実欠陥 4 件の修正）、
報告だけで済ませたのが 6 の残り半分（リポジトリ設定）。

**この文書自身が 5 回間違えた**（全部本文中に訂正として残してある）。
どれも「読んで書いた」ものが「実行して確かめた」ものに負けた:

| 書いたこと | 実測 |
|---|---|
| §5 のゲートは `set -e` の有無を見ればよい | 綴りであって性質でない。**正しい 2 本を告発し、生きた欠陥 4 本を「債務」として駐車した** |
| §5 の 12 本は挙動変更が怖いので直せない | 読んだら本当に壊れるのは 1 本だけ。4 本は直せたし、直すべきだった |
| §6 はコードでは塞げない | 半分は `test_scripts_allowlist.jl` が**事案の名前で**既に塞いでいた |
| §6 の対策は `strict: true` | 387 マージ/30 日・ピーク 106/日 対 CI 14 分 ⇒ **忙しい日はマージ不能**。却下 |
| 「測り直すほうが安い」 | **書いた時点で偽**。測定は scratch にしかなく、測り直すとは全部書き直すことだった（下記で解消） |

つまり誤りの分類を書く作業それ自体が、分類の §2（計器が盲目）と
§8（前提未検証）の実演になった。**ゲートを設計するときの正しい順序は、
性質を先に言葉にして、代理で測っていないか実物を 1 つ走らせて確かめること** —
CLAUDE.md §12 の「制約を緩める前に走らせろ」の裏返しで、
**制約を課す前にも走らせろ**が要る。

そして数え終えて残る所見は、**このリポジトリは「クラスを閉じる」のは得意で、
「クラスを閉じたことを一箇所に記録する」のが不得意**だということ。

番号が無いクラスは何人目か誰も知らない。この文書は 2026-08-22 時点のその番号であり、
**維持されない**（だから FROZEN）。

## 測り直すほうが読み直すより安い — いまはそれが本当
